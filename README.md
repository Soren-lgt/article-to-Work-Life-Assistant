# 工作生活助手 App

本机运行的个人「工作 + 生活」一体化管理工具：把每日待办、日常记账、开发事务、题库练习、小组协作收进同一个本地单页应用。纯前端实现，数据保存在本机浏览器 IndexedDB，支持导出 JSON 备份；另附 Electron 桌面壳，可打包成双击即用的 Windows 程序。

## 一、项目解决什么问题

日常学习/工作里，待办、记账、Bug 记录、刷题、小组任务往往散落在多个 App 或笔记本里，存在以下痛点，本项目针对性解决：

| 痛点 | 本项目的处理方式 |
|---|---|
| 待办、记账、开发任务、题库、小组任务分散在不同工具，来回切换 | 左侧 7 个导航模块统一管理，首页四张摘要卡一键进入对应模块 |
| 数据交给云端，担心隐私与离线不可用 | 数据只存本机 IndexedDB，不联网、无后端账号体系，导出 JSON 即可离线备份 |
| 重复记同一笔账会累加出错 | 同一账号 + 分类 + 日期只保留一条，再次写金额为**替换**而非累加 |
| 练习/考试缺即时反馈与错题沉淀 | 选择/判断题自动判分，问答按关键词命中判对，成绩历史可回看、错题可复查 |
| 小组协作缺最小闭环（申请、分配、提交、审核） | 组长/副组长/成员三角色，入组申请审核、任务看板、提交待审、确认/驳回、附件与操作日志 |
| 换设备/清缓存会丢数据 | 「数据与设置」支持全量导出 JSON，恢复时可选「覆盖恢复」或「合并导入」 |

定位边界：**本机多账号的单机工具**。「同组协作」是在同一浏览器内管理多个本地账号与本地小组，不做跨设备实时同步；代码题不在线运行，由本人/组长人工批改。

## 二、主要功能

左侧导航共 7 个模块（路由 hash：`#home` `#today` `#devwork` `#group` `#quiz` `#ledger` `#settings`）。

### 1. 首页总览（`#home`）
- 四张摘要卡：今日计划、同组计划、题库、每日记账；整卡点击跳转，卡片内勾选框/按钮不触发跳转。
- 今日待办可直接勾选并回写，与「今日计划」共享同一份数据。
- 汇总：今日待完成/总数、今日与本月记账金额、小组待审核与我的任务数、题库题量与最近一次成绩。
- 右下角问候角标。

### 2. 今日计划（`#today`）
- 按日期管理待办：标题、优先级（高/中/低）、备注；新增 / 编辑 / 删除 / 勾选完成。
- 前一天 / 后一天 / 「今天」切换；月度概览输出总数、完成、未完成并按天聚合。
- 记录结构字段：`title / date / priority / note / done / createdAt`。

### 3. 开发工作（`#devwork`）
- **开发任务**：按项目分组，状态流转「待开始 → 进行中 → 已完成」，可编辑标题、项目名、状态、备注。
- **Bug 记录**：状态「待处理 → 处理中 → 已修复 → 已关闭」，记录症状与备注，可编辑。
- **代码片段**：标题、语言、代码内容、描述；展开 / 复制 / 删除。

### 4. 同组计划（`#group`）
- 三角色：组长 `owner`、副组长 `deputy`（最多 2 名）、成员 `member`；组长可转让、任免副组长、移除成员、删除小组。
- 入组：组长/副组长邀请本机账号，或成员凭 **10 位加入码**申请，由组长/副组长审核通过/拒绝。
- 项目与任务看板：任务状态「待办 `todo` / 待审核 `review` / 已完成 `done`」；分配可带负责人与截止时间。
- 附件：成员上传（文本内容存 IndexedDB），全员可下载、仅上传者本人可删除；提交附件自动进入待审核。
- 操作日志（`opLog`）与站内通知（铃铛未读数），支持标记已读。

### 5. 题库（`#quiz`）
- 三大固定类别：**选择 / 问答 / 代码**；选择类细分单选、多选、判断。
- 题库（bank）归属于当前账号，并按「选择 / 问答 / 代码」类别划分；题库下题目可新增 / 编辑 / 删除；删除题库连带删除其题目。
- **顺序练习（practice）**：逐题作答、提交本题即时反馈正误。
- **考试模式（exam）**：跨当前账号全部题库随机抽题（默认 10 题，可改数量），倒计时显示，结束自动交卷。
- 判分规则：选择/判断按答案完全匹配；问答需命中全部关键词；**代码题不自动判分（人工批改）**。
- 成绩历史：只读回看作答明细（题干、我的答案、参考答案、对错），可删除历史记录；结果给出得分、正确率、错题数、用时。

### 6. 每日记账（`#ledger`）
- 预置「早餐/中餐/晚餐」三张分类卡片，可改名、删除，也可新建自定义卡片；删除卡片连带删除其记录。
- 记一笔：金额、备注、日期；**同一账号 + 分类 + 日期仅一条，重复写金额为替换**。
- 当天记录列表可删除；按天查看、按月汇总（各分类金额 + 合计笔数）。

### 7. 数据与设置（`#settings`）
- **数据概览**：各模块记录条数统计（「首页·今日计划与备忘」不在概览展示，但仍可在数据清理中单独清空）。
- **备份与恢复**：一键导出全量 JSON；恢复弹窗二选一——「覆盖恢复」（先清空再写入）或「合并导入」（保留现有、同 id 覆盖）。
- **数据清理**：分模块清空（今日计划、记账、开发工作、题库、同组计划、账号），以及二次确认的整体重置。
- **通用设置**：五套外观主题切换、默认打开页、站内通知开关、记账初始卡片管理。
- 账号管理集中在顶栏「登录 / 账号名」弹窗：创建、改名、设密码、退出、删除（删除账号级联清理其全部个人数据并退出所在小组）。

### 主题外观
内置五套主题：经典蓝白 `classic`、靛紫现代 `indigo`、墨绿沉稳 `forest`（默认）、暗夜青蓝 `night`、暖纸橘棕 `warm`；仅外观差异，不改变功能，选择存于本地 `localStorage` 的 `worklife.prefs`。

## 三、安装方法

### 3.1 网页版（推荐开发与日常使用）
运行期**无第三方依赖、无需 `npm install`**（纯原生 HTML/CSS/ES Module）。

前置环境：
- 任意 Chromium 内核浏览器（Chrome / Edge 等，需支持 IndexedDB）；
- 启动本地静态服务需要 **Python 3**（也可用任意静态服务器指向 `app/` 目录）；
- 仅运行自动化测试时需要 **Node.js 18+**。

获取代码后无需安装步骤，直接启动即可（见第四节）。

### 3.2 桌面版（Electron，可选）
业务前端 `app/` 零改动，桌面壳只提供窗口与内置静态服务。

```
cd desktop
npm install        # 仅首次：安装 electron 与 electron-builder
npm run dist       # 打包绿色目录版到 desktop/dist-win/win-unpacked/
```

日常使用：进入 `desktop/dist-win/win-unpacked/`，双击 `工作生活助手.exe`（整个目录需整体拷贝，不能只拷 exe）。桌面版数据独立于浏览器版，迁移方式见 `desktop/README.md`。

## 四、使用方法

### 4.1 启动网页版
Windows：双击根目录 `启动.cmd`（停止双击 `停止.cmd`）。

命令行（Windows / macOS / Linux 通用）：
```
python server.py            # 启动静态服务并自动打开浏览器，端口从 8000 起自动选空闲端口（8000-8049）
python server.py status     # 查看运行状态
python server.py stop        # 停止服务
```
- 服务目录为 `app/`，访问地址形如 `http://127.0.0.1:8000/`。
- 不建议直接双击 `app/index.html` 用 `file://` 打开：部分浏览器对 `file://` 下 IndexedDB 支持受限，统一走 `http://127.0.0.1` 最稳妥。
- 设置环境变量 `APP_NO_OPEN=1` 可跳过自动打开浏览器。

### 4.2 基本使用流程
1. 点顶栏「登录」打开账号弹窗 → 切到「注册」输入名称创建本地账号（可留空密码，也可设置可选本地密码）。
2. 左侧选择模块开始录入；首页摘要卡会随各模块数据自动刷新。
3. 需要离开当前页面时，在「数据与设置 → 备份与恢复」导出备份 JSON；换环境后用「从备份文件恢复」选择覆盖或合并。

### 4.3 运行自动化测试
无需安装依赖，仅用 Node 内置 `node:test` 运行器：

```
cd app
npm test              # 运行全部测试（当前 233 例）
npm run test:m0       # 单独跑某个里程碑（test:m0 ~ test:m8）
```

业务逻辑层（`app/js/lib/`）依赖统一仓储接口，测试使用内存适配器 `MemoryAdapter`，不触碰真实 IndexedDB。

### 4.4 桌面版
开发调试：`cd desktop && npm start`（开发态直接加载上级 `app/`）；打包：`npm run dist`。详细说明见 `desktop/README.md`。

## 五、输入输出示例

### 5.1 今日计划：新增一条待办
输入（表单）：标题「复习第二章习题」、优先级「高」、备注「重点看公式推导」。

写入 `todoplan` 仓库的记录形态：
```json
{
  "id": "todoplan_xxxxx",
  "accountId": "accounts_xxxx",
  "title": "复习第二章习题",
  "date": "2026-11-01",
  "priority": "高",
  "note": "重点看公式推导",
  "done": false,
  "createdAt": 1761900000000
}
```
勾选完成调用 `toggle()` 后 `done` 由 `false` 翻转为 `true`；月度概览 `monthSummary()` 输出：
```json
{ "month": "2026-11", "total": 8, "done": 5, "undone": 3, "byDay": { "2026-11-01": { "total": 2, "done": 1 } } }
```

### 5.2 每日记账：记一笔并查看日汇总
输入：分类「中餐」、金额 `12.5`、备注「食堂套餐」、当天日期。

写入 `ledgerRecord`；同日同分类再次填写 `15.0` 时，`addRecord()` 命中既有记录并**替换**金额（不累加）。`dayTotal()` 输出：
```json
{ "total": 15.0, "count": 1 }
```

### 5.3 题库判分
- 单选/判断 `gradeChoice()`：答案完全匹配返回 `1`，否则 `0`；多选按集合相等 `sameSet()` 判定。
- 问答 `gradeQa()`：题目关键词 `["HashMap","哈希"]`，作答文本需同时命中才判对：
```json
{ "correct": true, "hit": 2, "total": 2 }
```
- 代码题 `gradeQuestion()` 直接返回 `{ "correct": null, "manual": true, "score": 0 }`，等待人工批改。

交卷后成绩写入 `attempt` 仓库：
```json
{
  "accountId": "accounts_xxxx",
  "bankId": null,
  "mode": "exam",
  "score": 8,
  "total": 10,
  "details": [ { "questionId": "q1", "correct": true, "userAnswer": "B" } ],
  "startedAt": 1761900000000,
  "submittedAt": 1761900342000,
  "createdAt": 1761900342000,
  "timeSpent": 342000
}
```
结果页展示：得分 `8/10`、正确率 `80%`、错题 `2` 道；`timeSpent` 单位为毫秒，界面除以 1000 换算成秒展示（342000ms ≈ 342s）。

### 5.4 备份文件结构
「导出备份文件」下载 `worklife-backup-YYYYMMDD.json`，顶层结构（`stores` 遍历全部 20 个 object store；下方示例仅列出其中部分表，其余表以空数组 `[]` 一并导出）：
```json
{
  "version": 1,
  "exportedAt": 1761900000000,
  "app": "worklife-app",
  "stores": {
    "accounts": [],
    "todoplan": [],
    "ledgerRecord": [],
    "question": [],
    "task": []
  }
}
```
恢复时 `importAll(data, { mode })`：`mode:"replace"` 先清空对应仓库再写入；`mode:"merge"` 保留现有数据、同 `id` 覆盖；格式非法或缺 `id` 会抛出明确错误并中止。

```

ℹ pass 233
ℹ fail 0
ℹ skipped 0
```

## 六、技术栈与目录结构

- **前端**：原生 HTML + CSS + 原生 JavaScript（ES Module），无框架、无构建步骤、无运行期第三方库；弹窗统一由 `app/js/ui/modal.js` 的 `openModal / openConfirm / openPrompt` 承载。
- **存储**：浏览器 IndexedDB（库名 `worklife`，版本 1，共 20 个 object store）；主题与默认偏好存 `localStorage`（键 `worklife.prefs`）。
- **数据访问层**：`Repository` 统一接口 + `MemoryAdapter`（测试）/ `IdbAdapter`（浏览器）两套适配器，业务逻辑可在 Node 直接测试。
- **本地服务**：Python 标准库 `http.server`（`server.py`，零第三方依赖）。
- **测试**：Node 内置 `node:test`，覆盖数据 Schema、账号、各模块业务规则、判分、备份往返、弹窗契约与 HTML/主题结构。

```
.
├─ server.py                 # 本地静态服务：start / status / stop
├─ 启动.cmd / 停止.cmd        # Windows 双击启动 / 停止
├─ PRD.md / DEV_PLAN.md       # 产品需求与分阶段开发计划
├─ desktop/                   # Electron 桌面壳（详见 desktop/README.md）
└─ app/
   ├─ index.html             # 单页入口（7 个导航 + 7 个视图容器）
   ├─ css/app.css            # 全局样式 + 五套 data-theme 主题变量
   ├─ package.json          # 测试脚本（无需 npm install 即可跑 test）
   ├─ js/
   │  ├─ app.js              # 启动、路由、事件总线、顶栏、账号弹窗
   │  ├─ appstate.js         # 响应式状态中心（set/get/subscribe/emit）
   │  ├─ ui/modal.js         # 统一弹窗组件
   │  ├─ lib/                # 纯业务逻辑（Node 可测）
   │  └─ modules/            # 7 个 UI 模块：home/today/devwork/group/quiz/ledger/settings
   └─ tests/                 # node:test 用例（m0~m8、q 系列、j1、n1、n2 等）
```

## 七、数据与安全边界

- 数据仅保存在本机浏览器 IndexedDB；更换浏览器、清理缓存或卸载桌面前，请先导出备份 JSON。
- 本地密码并非明文存储：拼接固定前缀 `wl:` 后做 SHA-256（无随机盐；WebCrypto 不可用时退化为 `weak_` 前缀的简单哈希），仅作本机账号切换的弱校验，不构成网络安全防护。
- 「同组计划」是本机多账号 + 本地存储方案，不做跨设备同步；桌面版与浏览器版数据互相独立，可通过备份 JSON 迁移。
- 代码题不在线运行，作答由本人/组长人工批改。
